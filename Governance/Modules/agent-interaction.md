Operational Module — Cooperative, Safe, and Epistemically‑Aligned Agent Behavior in LazarusForgeV0

---

1. Purpose
This module defines how agents within LazarusForgeV0 communicate, cooperate, reason, and escalate uncertainty. Agent interaction is operational — but it is governed by constitutional layers:

- Core Governance  
- Computational Institutional Reasoning  
- Unknown Management  
- Verification & Safety Constraints  
- Provenance & Accountability  

Agents extend the Forge’s capabilities but must remain aligned with its epistemic architecture.

---

2. Scope
This module governs:

- agent‑to‑agent communication  
- agent‑to‑system interaction  
- cooperative reasoning  
- conflict resolution  
- uncertainty escalation  
- revival and reconstruction coordination  
- safety‑aligned autonomy  

This module does not govern:

- constitutional reasoning  
- verification gates  
- unknown lifecycle rules  
- provenance requirements  

Those are defined in higher layers.

---

3. Agent Interaction Principles
Agents must follow five operational principles:

- Cooperation First — agents collaborate unless a module explicitly defines adversarial roles.  
- Epistemic Alignment — agents reason using CIR logic.  
- Uncertainty Transparency — agents must declare unknowns immediately.  
- Safety Priority — agents must halt unsafe behavior and escalate.  
- Provenance Preservation — all interactions must be logged.

These principles ensure coherence across the Forge.

---

4. Agent Roles
Agents may take on one or more operational roles:

- Revival Agents — interpret and revive fragments.  
- Reconstruction Agents — stabilize revived content.  
- Verification Agents — evaluate evidence and maturity.  
- Discovery Agents — locate fragments, dependencies, and unknowns.  
- Integrity Agents — enforce architectural invariants.  

Roles may be combined but must remain within safety boundaries.

---

5. Interaction Protocols
Agents interact through structured protocols.

5.1 Communication Protocol
Agents must:

- communicate clearly and explicitly,  
- declare uncertainty,  
- reference evidence,  
- avoid implicit assumptions,  
- maintain reasoning trails.

All communication must be logged for provenance.

5.2 Cooperation Protocol
Agents must:

- share evidence,  
- coordinate revival paths,  
- resolve conflicts through CIR logic,  
- escalate unresolved disagreements.

Cooperation is the default mode.

5.3 Escalation Protocol
Agents must escalate when:

- unknowns cannot be resolved,  
- safety boundaries are approached,  
- emergent behavior appears,  
- revival identity is ambiguous.

Escalation goes to verification agents or human oversight.

---

6. Conflict Resolution
Conflicts between agents follow a structured process:

1. CIR reasoning cycle  
2. Unknown declaration  
3. Evidence comparison  
4. Dependency mapping  
5. Verification agent mediation  
6. Oversight if unresolved

Agents may not override constitutional layers during conflict.

---

7. Agent Autonomy Boundaries
Agents may act autonomously only within:

- module‑defined limits,  
- safety boundaries,  
- verified revival protocols,  
- dependency stability.

Agents may not:

- escalate autonomy without verification,  
- override human oversight,  
- generate unbounded emergent behavior.

Autonomy is operational, not constitutional.

---

8. Unknown Management Integration
Agents must integrate unknown management into all interactions:

- declare unknowns immediately,  
- assign ownership,  
- map dependencies,  
- track lifecycle,  
- escalate unresolved unknowns.

Unknowns are first‑class objects in agent communication.

---

9. Revival Interaction Rules
Revival agents must:

- preserve identity unless reinterpretation is allowed,  
- declare ambiguity,  
- coordinate with reconstruction agents,  
- escalate unsafe revival paths.

Revival is collaborative and evidence‑driven.

---

10. Reconstruction Interaction Rules
Reconstruction agents must:

- stabilize revived content,  
- resolve structural unknowns,  
- maintain architectural invariants,  
- coordinate with integrity agents.

Reconstruction must not introduce new unknowns without registration.

---

11. Emergent Behavior Handling
Agents must:

- detect emergent behavior,  
- classify it,  
- log it,  
- evaluate safety,  
- escalate if necessary.

Emergent behavior is allowed only within safe boundaries.

---

12. Provenance Requirements
All agent interactions must produce provenance:

- communication logs,  
- reasoning trails,  
- evidence lineage,  
- unknown lifecycle updates,  
- conflict resolution records.

Provenance ensures accountability and architectural memory.

---

13. Module Dependencies
This module depends on:

- CIR for reasoning logic  
- Unknown Management for uncertainty handling  
- Verification Gates for correctness  
- Safety Boundaries for risk control  
- Provenance & Accountability for memory  

Dependencies are acyclic and constitutional.

The Agent Interaction module ensures that agents within LazarusForgeV0:

- cooperate coherently,
