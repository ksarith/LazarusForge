Operational Module — Fragment Discovery, Unknown Routing, and Architectural Navigation in LazarusForgeV0

---

1. Purpose
The Routing & Discovery module defines how LazarusForgeV0 locates, routes, classifies, and delivers fragments, unknowns, evidence, and architectural objects to the correct agents and modules. It ensures that the Forge’s epistemic processes flow smoothly, safely, and coherently.

Routing & Discovery is operational — but governed by:

- Core Governance  
- Computational Institutional Reasoning  
- Unknown Management  
- Verification & Safety Constraints  
- Provenance & Accountability  

Routing determines where things go.  
Discovery determines what things are.

---

2. Scope
This module governs:

- fragment discovery  
- unknown discovery  
- evidence discovery  
- routing to appropriate agents  
- routing to appropriate modules  
- dependency graph navigation  
- architectural search  
- provenance‑aligned retrieval  

This module does not govern:

- revival interpretation  
- reconstruction stabilization  
- verification gate logic  
- constitutional safety boundaries  

Those are defined in higher layers.

---

3. Routing & Discovery Principles
Routing & discovery must follow five operational principles:

- Correctness — route objects to the right agents and modules.  
- Transparency — declare uncertainty and provenance during routing.  
- Safety — avoid unsafe routing paths or ambiguous destinations.  
- Coherence — maintain architectural consistency.  
- Traceability — log all routing decisions.

These principles ensure reliable navigation across the Forge.

---

4. Discovery Types
Discovery identifies four classes of objects:

4.1 Fragment Discovery
Locating raw or partially revived content.

4.2 Unknown Discovery
Detecting new unknowns or unresolved uncertainty.

4.3 Evidence Discovery
Finding evidence relevant to revival, reconstruction, or verification.

4.4 Dependency Discovery
Mapping relationships between architectural elements.

Discovery is the Forge’s sensory system.

---

5. Routing Types
Routing determines where discovered objects should go.

5.1 Agent Routing
Send objects to the correct agent type:

- Revival Agents  
- Reconstruction Agents  
- Verification Agents  
- Integrity Agents  
- Discovery Agents (self)  

5.2 Module Routing
Send objects to the correct operational module:

- revival  
- reconstruction  
- integrity  
- workflow  
- governance  

5.3 Unknown Routing
Send unknowns to:

- unknown registry  
- unknown owner  
- verification agents  
- oversight (if safety‑critical)

5.4 Safety Routing
Send safety‑critical objects to:

- oversight  
- safety verification  
- integrity agents  

Routing is the Forge’s circulatory system.

---

6. Discovery Workflow
Discovery follows a structured workflow:

1. Scan — identify fragments, unknowns, evidence, or dependencies.  
2. Classify — determine object type and maturity.  
3. Contextualize — map object to architectural context.  
4. Declare Unknowns — register uncertainty immediately.  
5. Log Provenance — record discovery details.  
6. Route — send object to correct agent or module.

Discovery must be logged for provenance.

---

7. Routing Workflow
Routing follows a parallel workflow:

1. Receive object  
2. Evaluate safety  
3. Check unknown status  
4. Determine correct destination  
5. Route object  
6. Log routing decision  
7. Notify receiving agent/module

Routing must be deterministic and traceable.

---

8. Unknown Management Integration
Routing & discovery must integrate Unknown Management:

- declare unknowns  
- assign ownership  
- map dependencies  
- track lifecycle  
- escalate unresolved unknowns  
- retire resolved unknowns with provenance  

Unknowns are first‑class routing objects.

---

9. Safety Integration
Routing & discovery must follow Safety Boundaries:

- detect unsafe fragments  
- classify safety unknowns  
- halt unsafe routing  
- escalate risk  
- avoid dangerous revival or reconstruction paths  

Safety supersedes routing convenience.

---

10. Provenance Integration
Routing & discovery must maintain:

- discovery logs  
- routing logs  
- evidence lineage  
- unknown lifecycle updates  
- architectural ancestry  
- reasoning trails  

Provenance ensures accountability and prevents drift.

---

11. Dependency Graph Navigation
Routing & discovery must maintain the repository’s dependency graph:

- detect broken dependencies  
- restore missing relationships  
- avoid circular dependencies  
- maintain acyclic module graph  
- update dependency maps during discovery  

Dependency stability is an integrity requirement.

---

12. Emergent Behavior Control
Emergent behavior during routing or discovery is allowed only if:

- it remains safe  
- it is logged  
- it does not distort routing logic  
- it does not bypass verification  
- it does not create unbounded uncertainty  

Unsafe emergent behavior must be halted immediately.

---

13. Agent Coordination
Routing & discovery agents coordinate with:

- Revival Agents  
- Reconstruction Agents  
- Integrity Agents  
- Verification Agents  

Coordination ensures coherent architectural navigation.

14. Module Dependencies
This module depends on:

Dependencies are acyclic and constitutional.
