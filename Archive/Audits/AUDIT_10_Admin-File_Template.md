- Findings (exact quote + location + severity + category):
  - **F1 — MAJOR, internal contradiction in the canonical template (two sections disagree on Challenges Problem-Statement Spec Gates).** Template Exemptions class 8: "They carry a File State table but Spec Gates is N/A by subtype design — they define problems, not specifications to be gated toward promotion." Challenges/ File Subtypes doctrine (§2 subsection): "**Spec Gates still apply, reinterpreted** — the six canonical gates test the problem statement's own rigor, not build-readiness", followed by a full per-gate reinterpretation table and "A Problem-Statement file's Spec Gates count tracks readiness for the repository to *act* on the problem". These two statements, in the same file, give opposite answers to whether the Spec Gates field of six named files (Biofouling, Critical_Minerals, Emergence, Planned_Obsolescence, Waste, Water) is N/A or a live 0–6 count. The exemption was added 2026-09-04 to close a documentation gap; the subtype doctrine is unversioned, and no reconciliation entry exists anywhere in this file (it has no Resolution Log — see F3). An auditor or retrofit pass reading class 8 would skip gate evaluation entirely; one reading the subtype doctrine would apply all six gates. Recommendation: one dated entry picking a single answer — either "N/A for promotion, live as reinterpreted act-readiness count" with the exemption text reworded to match, or true N/A with the reinterpretation table removed — and, per this file's own X8 lesson, a drift-indicator-style check that template sections citing each other get reconciled on every ruling pass.
  - **F2 — WARNING, schema drift inside the template (lean schema names fields the canonical schema does not define).** Challenges subtype doctrine: "The lean File State schema (Status, Version, Owner, Verification Ref, Ethical Anchor) is a deliberate, documented choice" — but §2's canonical File State table defines eleven fields with **no Version and no Owner**. Two consequences: (a) the subtype doctrine references a schema that exists nowhere in this file's own §2; (b) version metadata is left without a canonical home for non-Challenges files — Ethical_Constraints.md, for instance, carries version metadata (v0.16, synced 2026-09-03) with no template field to hold it, so the Session-1 resolution "absence of a Version field is conformant" is correct for full-schema files but the template never says where a version belongs when a file has one. Recommendation: either add Version/Owner to the documented lean schema example, or restate the lean schema as a subset of §2's actual fields.
  - **F3 — WARNING, undocumented self-application gap.** The template's Non-exempt clause reads: "All other files under `Admin/`, `Architecture/`, `Operations/`, `Challenges/`, and `Tests/` that carry doctrine, protocols, specifications, or gate definitions." File_Template.md is an Admin/ file carrying specification doctrine, is not on its own nine-class exemption list, and yet does not follow sections 0–11 itself: no File State table, no Scope Boundary, no Assumptions, no sidecar/Resolution Log, no Active Disputes, no Drift Indicators, no Ethical Anchor field. The header's dated Prior stack substitutes for File State + log. This is almost certainly a deliberate bootstrap (a template containing itself would be circular, and "the goal is not bureaucratic completeness"), but the exemption list's own meticulousness — it even documents *why* each class is exempt — makes the silent self-omission a genuine documentation gap rather than a self-evident one. Recommendation: add a tenth class ("This file — meta-template; header Prior stack serves as File State/Resolution Log; Ethical Anchor carried as the closing blockquote") or a one-line self-application note under Structure Overview. Cheap, and it closes the only file the exemption list forgot.
